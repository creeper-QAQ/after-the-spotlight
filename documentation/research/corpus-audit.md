## 正文可用的贡献

建议做一块“这些数字记录了什么”：以 94 条保留行作为明确分母，展示单位组或原主题标签构成。可用文案：“94 条台账记录，包含 29 种单位写法。人次、次数、金额和人数，分别留下不同场景的记录。”它贡献的是对资料结构的全量统计，说明为什么要逐条读清口径，不替代已核对的正文章节事实。

按单位组展开原行编号、原标签和来源即可追溯。例如次数组中 ZB014 对应台账 S4-002，显示层使用正文共用事实 `keyword-views` / `pub-douyin-2025`；人次组 ZB038 对应台账 S4-015，显示层使用 `ink-visits` / `pub-ink-2026`。这两条正文事实不能与其他待核实记录共享一个“已验证”徽标。

正文要描述持续学习，仍需同一人或同一批体验者的后续记录；本次统计不能计算观看到到访、到访到学徒或到访到消费的转化率。不能凭元数据归组推断哪些未读原文缺少追踪，也不能把本台账说成行业总体。

## 前端 API 与复算

默认导入 `corpusAudit`（`src/content/corpus-audit.ts`）。所有计数从当前数组重新计算，没有从 `summary` 抄取展示统计。

| API                                                          | 适合用途                                                                    |
| ------------------------------------------------------------ | --------------------------------------------------------------------------- |
| `counts`                                                     | 报告、指标、链接、笔记、子项与人物的各自分母。                              |
| `indicators.unitFamilies` / `topics` / `statuses`            | 全量保留行的单位、主题或原复核标签构成。                                    |
| `indicators.units` / `periodLabels` / `periodShapes`         | 字面单位与统计窗口元数据；时间写法分类不可称为有效统计期间。                |
| `indicators.topicUnitMatrix`                                 | 各主题内的单位构成；每一行的分母是该主题行数。                              |
| `leads.kinds` / `topics` / `statuses` / `urlGroups`          | 用途笔记分布；保留 URL 与全部笔记 ID。                                      |
| `sources.verification` / `usedSourceIds` / `unusedSourceIds` | 来源元数据与是否被现存主行引用；不是验证认证。                              |
| `displayOverlay`                                             | 同一批指标的当前显示层。自动读取 `report-view.ts`，保留正文共用事实的关联。 |
| `displayOverlay.linkedRows`                                  | 原台账来源、当前来源、原期间与显示期间的对应关系。                          |
| `deduplication` / `integrity`                                | 历史合并摘要的证明边界，以及键、外键、URL、摘要与实际行数的一致性。         |

分组对象统一含 `id`、`label`、`count`、`denominator`、`share`、`rowIds`、`sourceIds`、`sourceUrls`、`references`。`share` 为 0–1 的行占比，UI 可乘 100；`references` 只含既有来源元数据。线索本身没有来源 ID，使用其原 URL 和笔记 ID，不编造来源编号。

`indicators` 保留交付层；`displayOverlay` 读取当前适配器。ZB014、ZB038 的两个日期字段改为正文可读写法，因此显示层完整日期写法为 47 行、其他写法为 15 行；这不是测量期间本身变化。卡片与全量结构图必须声明使用哪一层。

运行 `node tests/corpus-audit.mjs` 可直接执行剥离类型后的实际 TypeScript。测试穷举每个分组的成员和分母，检查来源外键，并用仅存在于测试中的状态、单位、重复行、链接与正文事实变更证明统计随数据变化；不需要添加依赖或启动网页。该测试、TypeScript 全量检查与 `npm run build` 均已通过；本次构建包含正文中的审计组件。交付整站的页面检查由主任务继续完成。
